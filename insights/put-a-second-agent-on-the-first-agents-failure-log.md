YC holds data on 7,000 companies, 20,000 founders and hundreds of thousands of applications, and built an English-to-SQL agent over it a year or two ago. Blomfield describes that first agent as merely useful — it made him perhaps 10-20% more productive and saved hiring a data analyst — and it kept hitting edge cases, permission issues, and missing database indexes. The change he calls a "head explosion moment" was a *second* agent layered on top: it runs overnight, reads every query a human ran that day, sorts them into successes and failures, and opens pull requests fixing the previous day's problems. Run the same query the next morning and it works.

The generalisable move is that the failure log is already a specification for the next version of the system, and reading it is a job an agent can hold. Blomfield notes the same pattern applied to product telemetry — a company that ingests telemetry, finds where the product is breaking, opens pull requests and eventually auto-merges them. This is the concrete mechanism behind [[a-learning-mechanism-is-what-separates-a-loop-from-a-pipeline]] and a sharper version of [[ai-self-improvement-loop-accelerates-everything]] applied to an ordinary internal tool rather than to frontier models. It also compounds in the way [[proprietary-feedback-loops-widen-the-moat]] predicts, because the failure log is generated by your own users and nobody else has it — the same asset [[decision-traces-are-the-missing-data-layer]] argues most companies throw away.

Ashpreet Bedi (Agno) adds the step that has to come before the fix: sort each failure by cause. "A bad answer can have several causes. The agent might have found an old document, misunderstood an instruction, called the wrong tool, or hit a service failure. Each needs a different fix. Changing the prompt won't repair a broken integration." In his example, users keep correcting a support agent; the investigating agent finds that search keeps returning an old setup guide, fixes the guide and the retrieval, tests the change across user roles and phrasings before and after, and leaves tests behind. Looking across failures matters too: several agents failing on the same MCP server can share one root cause in a shared integration, fixed once for all of them. That is the same gate [[causal-triage-must-gate-automated-fixes]] puts in front of a production fixing agent.
